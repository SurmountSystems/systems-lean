elaborate left as **bootstrap-only, out-of-scope, or operator choice**. They

defines free as "named residual bar," not "reimplement Lean elaborator."

check/build the same host work Lake does (peer plan mission; goals bootstrap S4

implemented or what section-4 free bar currently requires without operator scope.

## WHAT full Lake replacement would require (vs that bar)

Full "Slake replaces classic Lake for elaborating SystemsLean" would need roughly:

1. **Parse / elaborate / typecheck** real host `.lean` (or migrate ~256 modules
   into a Slake dialect that covers the living host surface), not only
   Mult..Compose mini goldens (`*.slake-host` fragment dialect).
2. **Import graph + package manager jobs** for full `SystemsLean` / lake exes /
   theorem packages, not a fixed Mult+...+Compose companion set.
3. **Without-Lake (or freestanding) coverage** of that full develop loop as the
   **named free bar**, with DualResidual flip + lake (or successor) proof.
4. **Retire or re-scope** cold `just systems-lake` / `lake build` under
   `src/systems/`, claim-bool flip lake policy, and bootstrap prebuild of peer
   bins -- operator choice (a) vs (b) in free bar inventory row 3.
5. **Proof/tactic develop** if host free is meant to include `*Theorems` (design
   table 3a says proof develop is Lake today; Track 4 is orthogonal and does not
   alone flip host free).
6. **Evidence**, not greps: elaborator proof on DualResidual free flip; residual
   lockstep; surface-matrix Host residual free row; never slogans.

That is **explicit expand / successor elaborator work** after Mult-first peer,
called out as false today, out of scope for peer v0 and for Mult..Compose dual-ok,
and **held** for Track 3c until operator scopes the free bar.
