# Lake packages (Systems Lean monorepo)

ASCII. Map of the three **internal** Lake package ids in this checkout and how
to build the product host. Not residual. Not a claim flip.

These ids are tooling only. The project and language are **Systems Lean**. The
compiler is **Slake**. **Iso** was the original checkout-directory nickname when
this tree first started; it is not a product name.

## Three packages (internal)

| Package | Path | Role |
|---------|------|------|
| **Iso** | root `lakefile.lean` | **Internal** thin umbrella only. Requires the two workspace packages below. Root Lake id is **Iso** so it does not collide with **SystemsLean**. Historical directory nickname. Not the language name. |
| **SystemsLean** | `src/systems/lakefile.lean` | **Internal** product **host** elaborator package id: Systems Lean / Slake sources, freestanding emit drivers, host tools. This is where day-to-day host work and `lake build` for the freestanding product path live. |
| **SystemsLeanLean4** | `src/lean4/lakefile.toml` | **Internal** Lean-side dual examples package id only (JOIN-ALG classic Lean). Not freestanding product. No remote deps. |

Language and project names: **Systems Lean** (project + language), **Slake**
(compiler). Do not use Iso / SystemsLean / SystemsLeanLean4 in user-facing
prose as if they were product names. Detail: root `README.md` Names table,
`doc/vocabulary.md`.

## Offline / no mathlib

remote git dependencies and **no** mathlib:

## Freestanding product C vs classic Lake ahead-of-time C

| Story | Where | Role |
|-------|-------|------|
| **Freestanding product C** | `src/systems/emit/`, `out/freestanding-c/` | Slake product wire: runtimeless, no Lean managed runtime, no product GC. Generated by Lean emit (`just build`). Ownership: `src/systems/emit/host-owned-emit.md`. |
| **Classic Lake ahead-of-time C** | under `.lake/build/` (gitignored) | Managed Lean runtime intermediate from classic Lake. **Not** freestanding product. Do not ship as `out/freestanding-c`. |

Policy SSoT: root `AGENTS.md` (**Three languages only**, multi-language print
policy, freestanding / AOT C git policy).

## How to lake build SystemsLean

From monorepo root (preferred for product path):

```bash
just build          # freestanding emit + install out/freestanding-c
just systems-lake   # optional cold Lake elaborate of the host package
just check          # full suite (build first; CompCert matrix when ccomp on PATH)
```

Direct Lake (host package only):

```bash
cd src/systems
lake build                 # default library + registered lean_exe targets
lake build SystemsLean.Mult
lake exe slake-host-module-check
```

Root umbrella (requires both packages):

```bash
# from monorepo root with lean-toolchain resolved
lake build
```

Day-to-day host tools that must not call Lake on the step use without-Lake just
recipes (for example `just host-module-check-without-lake`). Claim bool flips
while bootstrapping still need Lake on PATH when the host elaborator is the
proof surface (`AGENTS.md` claim-bool proof rule).

## Safe import note

| Import class | Guidance |
|--------------|----------|
| Foundation units | Prefer `SystemsLean.Mult`, `SystemsLean.Linear`, `SystemsLean.Types` (and their theorem companions when proving) for grade / linear / kind surfaces. |
| Ordered IR / compose | `SystemsLean.IrProgram`, `SystemsLean.IrGraph`, `SystemsLean.HostCompose` for program and host compose surfaces. |
| Emit / product path / claim mains | `FreestandingEmit*`, `Capable*`, `ProductPath*`, `*Main` modules, and claim-exe roots are drivers and path machinery. Import them when you mean emit or claim tools; do not treat a thin Main as the foundation library API. |
| Host check harness | `HostModuleCheck*` / `HostImportGraph*` / `HostResidualShrink*` are structural host checkers (PARTIAL-STRUCTURAL; term-surface pilots Mult/Linear/Types only). Not full elaborator parity. |

Import the smallest role module that owns the surface you need. Avoid pulling
claim or subset-rebuild mains into foundation proofs.
