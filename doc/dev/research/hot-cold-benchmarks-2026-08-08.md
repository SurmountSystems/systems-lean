## Compile path comparison (living framing)

`just bench` is a **compile path comparison** (secondary tooling cost), not a
runtime answer to linear / no-GC / fastest C, and not only a Phase M residual checkbox.

| Arm | Path | What wall-clock means |
|-----|------|------------------------|
| **Arm A** | Systems Lean product path | Freestanding hot/cold product wire emit + without-Lake host develop tools |
| **Arm B** | classic Lean 4 + Lake | Hot `lake build` on the host package under `src/systems` (cold Lake skipped by default) |

**Question answered:** Systems Lean product path produces freestanding C (no garbage collection, no Lean managed runtime) and we compare its wall-clock cost to classic Lake elaborating the host package. Not "provably fastest C." Not full elaborator without Lake.

Living report: `doc/BENCH-latest.md` (regenerated by `just bench`). Scenario order and timers stay as in Methods below; the report groups results by arm with interpretation and output honesty.

**Phase 2 polish (2026-08-08):** primary `just bench` runs `just bench-lake-host`
**twice** so Arm B reports **B-hot first pass** (may be rebuild-heavy) and
**B-hot second pass** (true idle hot when the package is already Built).
Interpretation prefers second-pass real for the B/A ratio when second is ok, and
still notes first-pass when rebuild-heavy (real > 10 s). `bench-lake-host-cold`
stays **skipped** by default (separate recipe; destructive). Suite is not a wipe.

## 1. Methods

| Rule | Detail |
|------|--------|
| Timer | bash builtin `time` with `TIMEFORMAT='real %R user %U sys %S'` (matches `time -p` fields) |
| Serial | One lake / just / ccomp chain at a time. No parallel Lake (known `.olean` race). |
| Hot freestanding | Prebuilt writers under `src/systems/.lake/build/bin`; `just build` (no lake on hot path) |

| Wipe policy | **trash / mv only**. Never `rm -rf` project trees. |
| CompCert | `just product-compcert-matrix` (smoke + freestanding under ccomp + Mult under ccomp) |
