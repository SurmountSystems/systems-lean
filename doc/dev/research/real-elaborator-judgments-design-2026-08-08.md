## 4. Judgment classes (plain English)

To approach what classic Lake does on a package typecheck of SystemsLean, a
Slake (or HostModuleCheck successor) path would need named **judgment classes**.
Each class is a check category, not a greppable token list.

| Class | What Lake / Lean 4 does (plain) | Why greps are not enough |
|-------|----------------------------------|---------------------------|
| **J1 Package load** | Load lakefile / package roots; resolve module names to paths | Mostly met without-Lake (`host-package-roots`); not a term judgment |
| **J2 Import closure** | Resolve `import` / transitive deps; fail on missing or cycle | Seed import graph without-Lake (modules=206); not full *Main/harness policy as typecheck |
| **J3 Namespace and declaration identity** | Accept that a def/inductive/structure/axiom/theorem exists under a namespace | Closest to current PARTIAL-STRUCTURAL key decls |
| **J4 Kind surface** | Distinguish inductive vs structure vs axiom vs def vs theorem *as forms* | FOUNDATION-KIND-SURFACE band; still token presence, not well-formedness of binders |
| **J5 Definition typing** | Check each `def` / `abbrev` body has the claimed type under the local context | Needs term representation + type environment; greps accept ill-typed twins |
| **J6 Inductive / structure formation** | Check constructors, parameter/index telescopes, positivity / universe rules as the dialect requires | Structure name greps do not validate ctor arities or index sorts |
| **J7 Theorem / proof term check** | Elaborate proof terms (or tactic results) and ensure they inhabit the statement | *Theorems corpus greps names only; do not validate proof bodies |
| **J8 Universe and level constraints** | Assign and check universe levels on types and inductives | Absent from HostModuleCheck |
| **J9 Binder and multiplicity surface** | Check pi/lambda telescopes; for Systems Lean, grades 0/1/omega and linear use where the product dialect requires it | Product QTT honesty lives in Mult/Linear models; not full elaborator binder walk |
| **J10 Application and reduction** | Check applications well-typed; reduce / whnf as needed for equality | Absent; would need a real term kernel subset |
| **J11 Instance / class resolution** (if dialect uses them) | Find instances for typeclass constraints | SystemsLean mostly avoids heavy class search on freestanding path; still part of full Lean 4 parity |
| **J12 Mutual and where blocks** | Elaborate mutual inductives / defs consistently | Greps cannot order or mutual-check |
| **J13 Tactic elaboration** (optional later) | Run tactics to proof terms, then J7 | Explicit non-day-one; classic Lake does this for theorem scripts |
| **J14 Oleane / environment commit** | Persist checked constants into a package environment for dependents | without-Lake ELF checks files textually today; not environment merge |

**Lake-grade package typecheck** means roughly **J1-J12** on the develop library
set (and J13 where modules use tactics), with cold Lake remaining the diagnostic
oracle until evidence says otherwise.

**Day-one subset for SystemsLean residual (recommended):** grow **J5-J7** on a
tiny pilot band (start Mult), keep J1-J4 as living free-bar honesty, defer
J11-J13 and mathlib-scale environment features.

## 6. Evidence gates and dual-ok path (for later implement)

### 6a. Evidence gates (must run before any depth-token flip)

| Gate | Role |
|------|------|
| **E-good** | Named well-typed fixture or real module path accepted by the new judgment layer |
| **E-bad** | Ill-typed twin (wrong binder, wrong ctor arity, broken proof term) rejected; L0/L1 alone would still accept |
| **E-lake** | Cold `lake build SystemsLean.<Pilot>` exit 0 for the same good path; bad path is not claimed lake-green |
| **E-without-lake** | Day-to-day recipe (existing or successor without-Lake ELF) exit 0 on seed after change |
| **E-dual-pin** | HostModuleCheck + HostResidualShrink + Theorems + just greps agree on depth token and band string |
| **E-sub1kloc** | All touched HostModuleCheck*.lean under 1000 (FixtureTextsLater headroom tight ~996) |
| **E-hygiene** | `just hygiene` green |
| **E-no-forge** | FullHostElaborateRemains **false**; DualResidual free dual-ok **unchanged**; free/complete/PROVABLY **unchanged**; no full parity slogan |

### 6b. Dual-ok path (staged)

| Stage | Dual-ok meaning | FullHost | Free claimed | Parity row |
|-------|-----------------|----------|--------------|------------|
| Living (now) | L0+L1 green; PARTIAL-STRUCTURAL honesty | false | true (F1) | open |
| After Mult L2 pilot | TERM-SURFACE dual-ok **false** until E-good/E-bad/E-lake green; then dual-ok true for **Mult pilot only** | stays false | stays true | still open |
| After proof L3 pilot | PROOF-SURFACE dual-ok on named theorems only | stays false | stays true | still open |
| After package L4 | PACKAGE-ELABORATE dual-ok on seed library; surface-matrix Full classic elaborator parity may move **measured** only with explicit residual + lake proof | stays false | stays true | only then **measured** (never automatic) |

**Successor surface policy:** prefer extending HostModuleCheck with a documented
dialect subset over inventing a parallel grepping mill. If HostModuleCheck grows
past Sub-1-KLOC, split by role (checkers / fixtures / required decls) before
adding L2 bodies. Do **not** grow shell or Python mills.

**Dialect posture (carry-forward from A2):** hybrid -- foundation Mult-first term
dialect + staged real-module coverage. Prefer smallest judgment that rejects a
real ill-typed twin over day-one full Lean 4 elaborator.

### 6c. What cold Lake keeps

Even after L2/L3 pilots:

- wipe-bootstrap full elaborate;
- claim-proof lake when AGENTS requires elaborator proof on pin flips while Lake
  is still the bootstrap elaborator for that surface;
- diagnostic full-package sanity.

FullHostElaborateRemains **false** continues to mean "not day-to-day," not
"Slake already matches Lake typecheck."
